RELATIONAL DATA MODEL:
FORMAL DEFINITIONS
l

l

A tuple t is an ordered sequence of n values (v1, v2, …, vn) such
that vi Î dom(Ai) or is null.
The Cartesian product over dom(A1), dom(A2), …, dom(An) is the
set of all possible tuples {t1, t2, …, tm} with first element Î dom(A1),
second element Î dom(A2), … and last element Î dom(An).
Example: Let dom(name) = {Lee, Cheung} and dom(grade) = {A, B, C}.
Then the Cartesian product of the two domains is
dom(name) ⨉ dom(grade) = {<Lee, A>, <Lee, B>, <Lee, C>,
<Cheung, A>, <Cheung, B>, <Cheung C>}

☞ The Cartesian product is not commutative since the domain order matters.
l

A relation instance (or simply relation) r over relation schema R is
r(R) Í dom(A1) ⨉ dom(A2) ⨉ … ⨉ dom(An).
☞ A relation instance is any subset of the Cartesian product of its domains.

Example: r(R(name, grade)) = {<Lee, A>, <Cheung C>} Í dom(name) ⨉ dom(grade)

RELATIONAL DATA MODEL:
PROPERTIES OF RELATIONS
l

Tuples in a relation are not ordered, even though they are
represented in a tabular form.

☞ Recall that a relation is a set of tuples.
l

All attribute values are atomic.

☞ Multivalued and composite attribute values are not allowed in a
relation, although they are permitted in the E-R data model.

l

The degree of a relation is the number of attributes.

l

The cardinality of a relation is the number of tuples.
☞ This is not the same as the cardinality constraint in the E-R data model.

RELATIONAL DATA MODEL: CONSTRAINTS
Entity integrity constraint
If X is a primary key for R, then X cannot contain null values.

Referential integrity (foreign key) constraint
S(kS,…)

T(…, fkS)

Given two relations S and T, relation T may reference relation S via a set of
attributes fkS that forms the primary key kS of S.
The attributes fkS in T are called a foreign key.
The value of the foreign key fkS in a tuple of T must either be equal to the
value of the primary key kS of a tuple in S or be entirely null.
☞ A foreign key represents a 1:1 or 1:N relationship.

E-R SCHEMA TO RELATION SCHEMAS REDUCTION:
REFERENTIAL INTEGRITY ACTIONS
S(kS,…)

T(…, fkS)

If relation T contains an attribute fkS that is the primary key kS of relation S, which can
be specified as the foreign key constraint
foreign key (fkS) references S(kS)
then the value of fkS in a tuple of T must either be equal to the value of the primary
key kS of a tuple in S or be entirely null.

To enforce this constraint, relation schemas require the following actions.
If in an E-R schema the referencing entity has total participation

on delete cascade - Delete all T tuples with foreign key values that match the
primary key value of the deleted S tuple.
If in an E-R schema the referencing entity has partial participation

on delete set null - Set to null the foreign key value of all T tuples whose foreign
key value matches the primary key value of the deleted S tuple.

REDUCE RELATIONSHIPS
For each binary relationship R:

– Create a new relation schema RR.
– Include as foreign key attributes in relation RR the primary keys of the
entities related by relationship R.
– Include attributes aR of relationship R, if any, as attributes of relation RR.
– The primary key for relation RR is
Ø binary 1:1 relationship ⟹ the primary key for either entity.
Ø binary 1:N relationship ⟹ the primary key for the entity on the
N-side of the relationship.
Ø binary N:M relationship ⟹ the union of the primary keys for the
two participating entities.
Add: a foreign key constraint for each foreign key with the referential integrity
action on delete cascade.

☞ This reduction minimizes null values.
