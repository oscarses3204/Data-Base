DATA MODEL (cont'd)
l

A document is an ordered set of key-value pairs.
– Documents are like rows in a relational database, but each row
(document) can have a different structure.
– A key-value pair is referred to as a field.

l

A collection is a set of documents.
– Collections are like tables in a relational database.
– Each document in a collection has a special field (key-value pair)
where the key is named _id and the value must be unique within a
collection.
Ø The value of the _id field can be user-defined or auto-generated by
MongoDB.

l

A database consists of one or more collections.

MONGDB DATABASE DESIGN
l

A MongoDB database has a flexible schema, which means:
– documents in a collection are not required to have the same set of
fields.
– a field's data type can differ between documents in a collection.

l

l

l

In practice, documents in a collection usually share a similar
structure.
Document validation rules can be specified to ensure
consistency in the schema.
A key decision in designing a MongoDB database involves
specifying how relationships between data are represented.
– Relationships can be represented using either references or
embedded data.

MONGDB DATABASE DESIGN: EMBEDDED DATA
l

Embedded data represent relationships between data by storing
related data in a single document in either a field or an array.
– Allows related data to be retrieved or updated in a single operation.
– Provides better performance for read operations.

– May require data duplication since data is denormalized.

MONGODB QUERY LANGUAGE (MQL)
l

l

MongoDB Query Language (MQL) is the interface by which
clients interact with a MongDB database.
MQL commands can be executed
– interactively using either the MongoDB shell (mongosh), a JavaScript
interpreter, or MongoDB Compass a GUI that allows a database to
be accessed using a desk-top-like environment.
– from within a programming language using an appropriate driver.

l

l

MQL supports basic create, retrieve, update and delete (CRUD)
operations.
MQL also supports an aggregation framework, based on the
concept of a data processing pipeline, where documents enter a
series of stages that filter and transform them.

AGGREGATION EXPRESSIONS
l

Aggregation expressions are used to query and operate on
documents and can be:

– a field path with a $ prefix followed by the field's path in the
document being accessed (e.g., '$district' – the field path for the district
field of clients, '$accounts.balance' – the field path for the balance field of
documents in the embedded accounts array).
– an operator with a $ prefix (e.g., $cond, $expr, $count, $sum, $avg, …
(mostly use in the aggregation framework—see later lecture).

– a user or system variable with a $$ prefix followed by a fixed name.

l

These three categories of aggregation expressions can be
composed when operating on input documents.

☞ The dot notation is used to access the fields of
embedded documents of a collection.

☞ When using the dot notation, the field name and embedded field
name must be enclosed in (single or double) quotation marks.

BOOLEAN EXPRESSION OPERATOR: $AND
$and: [{predicate1}, {predicate2}, …, {predicaten}]

The $and operator performs a logical and operation on an array of one or
more predicates and selects the documents that satisfy all the predicates.

☞ The predicates are specified as an array of predicates.

Query: Find the name of clients who live in Islands district whose
credit rating is less than 8.
db.clients.find({$and: [{district: 'Islands', rating: {$lt: 8}}]},
{_id: 0, name: 1});

Query result:

{name: 'Mary Kwan'}

Since and is the default boolean operator, this query can also be expressed as:
db.clients.find({district: 'Islands', rating: {$lt: 8}},
{_id: 0, name: 1});

Query result:

{name: 'Mary Kwan'}

☞ These two queries get identical results if and only if
the fields in all the predicates are different.

CONDITIONAL EXPRESSION OPERATOR: $COND
$cond: {if: booleanExpression, then: trueCaseExpression, else: falseCaseExpression}
$cond: [booleanExpression, trueCaseExpression, falseCaseExpression]
The $cond operator is an if-then-else statement that returns the value of the:
– trueCaseExpression if booleanExpression evaluates to true;

– falseCaseExpression if booleanExpression evaluates to false.

Ø Both the trueCaseExpression and the falseCaseExpression must be provided.
Ø If there is no action to take for the else (false) branch, then the REMOVE system
variable can be used to specify that no action should be taken.

The $cond operator can be used:

– in a projection to selectively project fields based on a condition.
– to specify different update actions based on a condition.

– to control the flow of data in an aggregation pipeline and apply different
transformations based on a condition (see later lecture).

The $switch operator evaluates a series of predicates. When it finds a
predicate which evaluates to true, it executes a specified expression and
breaks out of the control flow.
Ø branches is an array of control branch documents with fields case and then.
Ø default is optional and is taken if no branch case evaluates to true.

☞ The case statements do not need to be mutually exclusive.

QUERY PREDICATE OPERATOR: $EXPR
$expr: {expression}
The $expr operator allows the use of expressions within a query predicate
and is required when
– comparing two fields from the same document.

– performing a calculation based on values from multiple fields in each
document and then comparing the calculation to a constant.
Query: Find the name of the branches, their liabilities and their assets
where their assets are less than their liabilities.
db.branches.find({$expr: {$lt: ['$assets', '$liabilities']}},
{_id: 0, branch: 1, liabilities: 1, assets: 1}
);
Query {branch: 'Diamond Hill', liabilities: 55000, assets: 0}
result: {branch: 'Pacific Place', liabilities: 120000, assets: 40000}

☞ The $expr operator requires that aggregation expressions (i.e.,

prefixing a field name with $) be used to reference document fields.

REGULAR EXPRESSION OPERATOR: $REGEX
field: {$regex: /pattern/, $options: options}
The $regex operator is used to match patterns in strings.
Ø The default pattern matching is case sensitive.
Ø options such as i, for case insensitive, can be specified.

Query: Find the name of clients whose name begins with Steven

either ‘v’ or ‘ph’ followed by ‘en’ followed by any other
characters).

{_id: 0, name: 1});

{name: 'Steven Chan'}

Query: Find the name of clients with a double vowel (i.e., double a,

db.clients.find({name: {$regex: /[aeiou]{2}/, $options: 'i'}},
