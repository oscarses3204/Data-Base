14.3

B+-TREE INDEX
l

Disadvantage of ordered-index (aka indexed-sequential) files
– Performance degrades as the file grows due to overflow pages.
– Periodic reorganization of the entire file is required.

l

Advantage of B+-tree index files

– Balanced tree ⟹ every path from root to leaves is the same length.

– Automatically reorganizes itself with only small, local changes in the
presence of insertions and deletions.

– Reorganization of entire file is not required to maintain performance.
l

Disadvantage of B+-trees

– Extra insertion, deletion and space overhead.

The advantages of B+-trees far outweigh their disadvantages.
They are used extensively in all commercial DBMSs.

B+-TREE: OBSERVATIONS
l

l

l

l

Since the inter-node connections are given by pointers, the
“close” pages need not be “physically” close on secondary
storage (i.e., there is no need to store pages sequentially).
The non-leaf levels of the B+-tree form a sparse index (i.e., not
every search-key value is present in the internal nodes).
Since a B+-tree contains a relatively small number of levels
(logarithmic in the size of the data file), search can be
conducted efficiently.
Insertions and deletions to the data file can be handled
efficiently, as the index can be restructured in logarithmic time.

B+-TREE: QUERY
l

Find all records with a search-key value of v.
1. Start at the root node.
Ø If v < Kn–1 (there are n pointers in the node, i.e., v is not larger than all
values in the node) follow pointer Pj, where Kj is the smallest search-key
value > v (i.e., follow the pointer to the left of Kj).
Ø Otherwise, if there is an entry with search-key value Kj = v, follow pointer
Pj+1 (i.e., follow the pointer to the right of Kj).
Ø Otherwise, if v ³ Kn–1 the last value in the node, follow pointer Pn (i.e.,
follow the last pointer in the node).

2. If the node reached by following the pointer in step 1 is not a leaf
node, repeat step 1 on the node reached, and follow the
corresponding pointer.
3. Reached a leaf node.
Ø If for some i, key Ki = v follow pointer Pi (i.e., follow the pointer to the left
of Kj) to the desired record or list of pointers to records.
Ø Else no record with search-key value v exists.

B+-TREE UPDATE
l

l

When a record is inserted or deleted from a data file, indexes on
the file must be updated.
Updates to a record can be done as a deletion of the old record
followed by an insertion of the updated record.

☞ Only need to consider B+-tree

insertion and deletion operations.

l

To maintain the B+-tree properties, it may be necessary to
– split a node when doing an insertion (node overfull).
– coalesce (combine) nodes when doing a deletion (node underfull).

☞ Must ensure that balance is preserved when doing an update

(i.e., all paths from the root to the leaves are the same length).

STATIC HASHING DEFICIENCIES
l

In static hashing, a function h maps search-key values to a fixed
set B of page addresses.
– Databases usually grow over time.
– If the initial number of fixed pages is too small, performance will
degrade due to too many overflows.
– If the file size at some point in the future is anticipated to grow and
the number of pages allocated accordingly, a significant amount of
space will be wasted initially.
– If the database shrinks, again space will be wasted.
– One option is periodic re-organization of the file with a new hash
function, but this is very expensive. Why?

l

These problems can be avoided by using techniques that allow
dynamic modification of the hash function (i.e., dynamic
modification of the number of pages to which we hash).

INDEX SELECTION CONSIDERATIONS
l

Types of accesses supported efficiently
– B+-tree indexes are used extensively in database systems for
searching (~90% of uses cases).
– Hash indexes are not used extensively for searching since they do
not support range searches ⟹ used mainly for in-memory hashing.
– Secondary indexes are not good for queries that retrieve many
records as the same page may be retrieved multiple times.

l

Update time
– When a data file is modified, every index on the data file must be
updated.

l

Space overhead
– The index should be, in general, much smaller than the data file.

INDEXING: SUMMARY
Indexing reduces the overhead of searching by trading space
(storage overhead) for time (faster search).
Dense and sparse tree index

Dense: contain entries for every search-key value at the leaf level.

Sparse: contain entries for only some search-key values at the leaf level.

Clustering and non-clustering (secondary) index
Clustering: file is ordered on the search-key values.

Non-clustering: file is not ordered on the search-key values.

Indexing methods

B+-tree: use a search-key value to search a tree-index to find an index
entry that points to the data file.

Hashing: apply a function to the search-key value to directly access an
index entry that points to the data file.
