INDEXING BASIC CONCEPTS: RECAP
Search key The attribute, or set of attributes, used to search for
records in a file.

☞ Do not confuse with the concept of primary or candidate key.
Ø A primary key is always also a search key.
Ø A search key is not necessarily a primary key (it can be any attribute).

– In the preceding example, the search key was hkid since records
were found given a value for hkid.

☞ To find records given a person's name (or another attribute)
additional indexes need to be constructed.

Index file A file consisting of records (called index entries) of the
form <search key, pointer>.
– Index files are typically much smaller than the original file as they do
not store all the attributes, but only search-key values and pointers.

ORDERED INDEX
l

The index constructed for hkid is an ordered (or tree) index.

– In each page, the index entries are ordered (sorted) on the search
key (e.g., hkid).

– Searching for a record always starts from the tree root and follows a
single path to a tree leaf using a search key of the record.
– An additional access is then required to retrieve the record from the
data file.
Page I/O cost: tree height (i.e., number of index levels) plus 1.

14.2.1

DENSE VERSUS SPARSE INDEX
Dense Index Contains an index entry in the leaf-level index
pages for every search-key value in the file.
Sparse Index Contains an index entry in the leaf-level index
pages for only some search-key values in the file.

Example: The hkid index only has index entries for the first record in
each page of the file ⟹ sparse index.

– In general, there is an index entry for every data file page corresponding
to the minimum search-key value in the page.
– To locate a record with search-key value K (single-level, sparse index):
Ø Find the index entry with the largest search-key value ≤ K.
Ø Follow the associated index entry pointer to the data file page.
Ø Starting at the first record on this page, search the data file sequentially until
the search key value is found or the end of the data file is reached.

☞ Sparse indexes require less space and less maintenance

overhead for insertions and deletions than dense indexes.

14.2.5

INDEX ON COMPOSITE SEARCH KEY
l

If a query often uses certain combinations of attributes together
(e.g., hkid and age), then creating an index on this attribute
combination can speed up retrieval.

☞ A composite search key is a search key that
consists of more than one attribute.

l

l

The index structure for a composite search key is the same as
that for a single attribute search key.
For a composite search key, the ordering of search key values
is the lexicographic ordering.
Example: For two search keys (a1, a2) and (b1, b2):
(a1, a2) < (b1, b2) if either a1 < b1 or a1 = b1 and a2 < b2

– This is basically the same as alphabetic ordering of words.
