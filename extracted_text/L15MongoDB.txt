AGGREGATION FRAMEWORK
In MongoDB, analytics on documents are performed via an
aggregation framework which is based on the concept of a data
operation pipeline.

documents

stage 1

documents

…

documents

Input documents from a collection form a data stream that is
passed through one or more stages (processing units) each of
which performs an operation (processing task) on its inputs.

☞ The inputs and outputs of all stages are documents.
☞ Each stage transforms the set of input documents
into a new set of output documents based
on the operation(s) performed in the stage.

AGGREGATION STAGE: $PROJECT
$project: {projection}
The $project stage passes only the specified document fields to the next
pipeline stage.

Ø projection is a JSON document that specifies the fields to include in or exclude
from the input documents the same as that used in the find method. However, in
an aggregation pipeline it cannot be an empty document.
Ø The specified fields can be existing fields from the input documents or newly
computed fields.

Ø To add a new field or to rename an existing field, a field name is specified, and
its value is set to some expression.

☞ The output documents contain only the projection fields.

Query: Find the districts of clients.
db.clients.aggregate([
{$project: {_id: 0, district: 1}}
]);

AGGREGATION STAGE: $MATCH
$match: {queryFilter}
The $match stage passes the documents that match the queryFilter to the

Ø queryFilter is a JSON document that specifies the selection criteria the same as

☞ The output contains only those input documents

AGGREGATION STAGES: $SORT; $LIMIT; $SKIP
$sort: {field1: sortOrder, field2: sortOrder, …}
The $sort stage sorts all input documents according to the specified sort
order(s) and outputs them.

Ø sortOrder can be 1 (ascending), or -1 (descending) and is evaluated from left to
right when sorting on multiple fields.

$limit: integer
The $limit stage restricts the number of output documents to integer.

$skip: integer
The $skip stage skips over integer number of input documents and outputs
the remaining documents.

☞ The content of the documents is not changed;
they are either reordered ($sort) or their
number is reduced ($limit and $skip).

$group: {

A $group stage groups documents according to a group key and outputs
one document for each unique group key.

Ø _id: fieldPathList specifies the field(s) on which to group (i.e., the group key). If
fieldPathList is specified as null, or any other constant value, the $group stage
returns a single document that aggregates values across all input documents. If
fieldPathList consists of more than one field, then the list must be enclosed in curly
brackets { } and each field path must be named, e.g.,
_id: {clientId: '$clientId', accountNo: '$accounts.accountNo'}.
Ø field: {accumulator: expression} is optional and is computed using accumulator
operators. A single $group stage can contain multiple accumulator operators.

☞ The output documents contain only the group key
and the result of any accumulator operators.

The $median accumulator syntax is: $median: {input: number, method: 'approximate'}
The $median accumulator returns an approximation of the median, the 50th percentile, as a scalar value.
The $trunc arithmetic expression operator syntax is $trunc: [number, place] where number is the field value to
truncate and place specifies the number of decimal places. If place is omitted, then place defaults to 0.

$count: {'fieldName'}
A $count stage is used to count the number of documents that reached that

Ø A single document is passed to the next stage that contains fieldName with the

AGGREGATION STAGE: $UNWIND
$unwind: {path: fieldPath}
The $unwind stage deconstructs an array field in the input documents and
creates one output document for each array element.

Ø Each output document is the same as the input document except that the value
of the specified array field is replaced by one of the array elements (i.e., one
document is output for each array element).
Ø The path keyword is optional.

Ø If the field specified by fieldPath is not an array and is not null or absent, then one
document is output with the field (i.e., the document is not changed).

Ø By default, no document is output if the array field value is null, absent or an
empty array. This can be changed by specifying - preserveNullAndEmptyArrays: true as an optional argument to the $unwind stage.

☞ The output contains one document for
each element of the specified array.

☞ Since accumulators cannot be applied to array fields,

unwinding is required to use accumulators on array fields.

ACCUMULATOR OPERATOR: $ADDTOSET
$addToSet: {field1: value1, …}, {modifiers}
The $addToSet operator adds a value to an array only if the value is not
already in the array.

Ø If field is absent from the document, then an array field named field is created with
the specified value as its element.
Ø The $addToSet operator only ensures that there are no duplicate elements added
to the set; it does not affect existing duplicate elements.
Ø The optional $each modifier adds multiple values to the array field. The multiple
values are specified as an array value for the $each modifier, i.e.,
$addToSet: {field: {$each: [value1, value2, …]}} }.

☞ The output contains the array field added by the $addToSet

operator in addition to any other fields added by other stage
operators.

☞ The $addToSet operator can be used to remove duplicate values
(i.e., keep only unique values).

ACCUMULATOR OPERATOR: $PUSH
$push: {field1: value1, …}, {modifiers}
The $push operator appends a specified value to an array.

Ø If field is absent from the document, then an array field named field is created with
the specified value(s) as its element.
Ø Elements are added at the end of the array and duplicate elements are retained.
Ø If a value is an array, then the whole array is added as a single array element.
Ø The following optional modifiers are allowed:

• $each adds multiple values to the array field. The multiple values are specified
as an array value for the $each modifier, i.e.,
$push: {field: {$each: [value1, value2, …]}}.
• $slice limits the number of array elements; requires use of the $each modifier.
• $sort orders the elements of the array; requires use of the $each modifier.
• $position specifies the location in the array at which to insert the new
elements; requires use of the $each modifier.

☞ The output contains the array field added by the $push operator
in addition to any other fields added by other stage operators.

MQL Notes

1. Aggregation expressions
cannot be used in the
$lookup aggregation stage.
2. All field and collection
names must be enclosed
in quotes.

The $lookup stage performs a left outer join on the input documents to a
collection in the same database by adding a new array field to each input
document that contains the matching documents from collectionToJoin.

Ø collectionToJoin specifies a collection in the same database to perform the join with.
Ø fieldFromInputDocument specifies a field from the input document.
Ø fieldFromCollectionToJoin specifies a field in collectionToJoin.

Ø outputArrayField specifies the name of the added array field which will contain the
matching documents from collectionToJoin.

☞ The output documents are the same as the input documents
except that an array field is added containing the matching
documents from the collection being joined.

MONGDB DBMS: SUMMARY
l

l
l

MongoDB is an open-source, schemaless NoSQL DBMS
designed for horizontal scaling.
Data is stored in JSON-like collections of documents.
Unlike relational databases that rely on foreign keys and join
operations, MongoDB supports:

– references which use unique identifiers to establish relationships
between documents.
– embedded data which store related data in a single document
(reducing the need for joins).
l

The MongoDB query language (MQL) supports basic database
operations as well as analytics on documents via an
aggregation framework.
